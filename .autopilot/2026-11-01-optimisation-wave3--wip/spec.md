# Спецификация: волна 3 — производительность (S5) и UX (S6)

Код как он есть — `notes.md` (читать первым, там точные имена и строки). Границы — `interfaces.md`.

## Задача
Платформа v6 тяжёлая и «дёрганая»: страница ~4 MB с текстами всех четырёх языков, каждое действие и каждый 2-секундный тик перерисовывают всё через `render()`, длинные списки режутся `.slice`, все демо-данные строятся при загрузке. А работать в ней неудобно: нет палитры команд, настройки не помнятся, пустые/загрузочные/ошибочные состояния у каждого списка свои, подтверждения — окнами, три разных места для тревог/входящих/задач, у всех 11 ролей одна и та же стартовая.

## Порядок и параллельность
Волна 3 стартует после слияния S4 (S4 влит, v6.4.0). S5 (производительность) и S6 (UX) идут параллельно: S5 — тикеты 01, 02, 04, 05, 09; S6 — 03, 06, 07, 08. Общее ядро правит один тикет за раз.

## Решение
Страница лёгкая и быстрая, интерфейс запоминает пользователя и помогает работать: Ctrl+K, «Отменить» вместо подтверждений, единый центр уведомлений, стартовая под роль, сценарии демо в один клик.

## Решения по реализации
- **Версия.** Волна выходит как 6.6.0 (6.5.2 — база). Каждый тикет не поднимает `VERSION`; поднимаю один раз при приёмке.
- **R01:** вырезание на сборке сканером вызовов `T(` с учётом строк, шаблонов, скобок и регэкспов; заменяет вызов на `T(<выбранный язык>)`, `T` остаётся `(...a)=>a[LI]??a[0]`; kk без значения → ru. Несканируемые формы (`HQ`, `tx`, `DT`, `ECO_BL`, `NM`) трогать только если вырезание проверено тестами; иначе вне потолка — вес всё равно упадёт > 25 %.
- **R02:** режим `--split` — дополнительный выход, не меняет основной; граф зависимостей файлов по `addTab/DRAWERS/ACT/HOOKS` проверяется на сборке.
- **R03:** `render()` остаётся единственной точкой входа для полного рендера (обёртки 001-shell-ext, 330-driver-app, help, a11y сохраняются); новые `renderRegion` пользуется теми же хуками после-рендера (a11y, syncUrl, helpDecorate) только для затронутой области; действия объявляют область (`ACTION_DEFS.region`, по умолчанию `main`).
- **R06:** ленивые коллекции через `lazy(name, fn)` + геттер на `S`; порядок инициализации и сид сохраняются; `demoReset` снимок строится лениво.
- **R07:** использует `S.gs` (`gsLines/gsDb`), `ACTION_DEFS`, меню по ролям; не вводит второй поисковый индекс.
- **R10:** работает поверх реестра действий (`registerAction`) — флаг `undo`.
- **R12:** хранилище — только наложение; новых источников не вводить.
- **R13:** сценарий = параметр сида + пресет значений; применяется через `demoReset(scenarioId)` и перезагрузку состояния, где иначе несогласованно.
- **Тесты:** каждый тикет добавляет группы в новые файлы `platform-src/tests/i1…` и чинит старые, чьё поведение изменилось (с комментарием). Полные 4 шарда зелёные до приёмки. Бюджеты (`budget.json`, `perf-budget.json`) пересматриваются вниз после R01.
- **Порядок и конфликты:** ядро (`core.js`, `001-shell-ext.js`, `002-a11y.js`, `base/*`) правит один тикет за раз.
