Overall picture: every 0.3.11 screen, tab and card now exists in v6 with the same labels (the P1–P6 ports are complete at screen level). The remaining differences are almost all in the rules behind the cards: permission gates on write actions, server-side 409 guards (delivery with open stops, quality hold, gates re-run at departure, hub guard), automatic side effects (alarm → release withdrawal, reading → alarm, decision → order outcome / customer event), the hub filter on secondary lists, and rule constants (weather levels, door timer, planning rows). Cross-cutting themes that appear in several parts:

1. **One alarm store vs two** (D-76, D-41, E-44, A-10): v6 keeps `S.alarms` (Dashboard) and `S.inc` (Security) apart, so cold-chain alarms never reach Security, manual readings raise no alarm, and an alarm does not withdraw a release.
2. **Permission gates missing on write actions** (E-4, E-25, E-42, C-16, C-61, B-59, B-63, A-62): generate / ESF / release / withdraw / save plan / scan are open to every reader; driver role is not scoped to own trips.
3. **Server guards of 0.3.11 not re-implemented in the model** (B-64, B-66, B-27, B-21, B-74, E-61, E-101, A-73, D-82): v6 state transitions skip the 409 checks that 0.3.11 applies on the backend.
4. **Hub filter applied to the main list only** (A-30, A-33, A-45, B-38, D-82): secondary lists, inbox excerpt, weather tiles, planning pool and incidents ignore the shell hub segment.
5. **Partner hand-over not projected onto loads** (C-25, C-26, C-49, B-75): `o.handed` is never set, so the locked rows and exclusion from the load calculation are dead code.
6. **Deep links drop the id** (A-20, B-14, B-17, B-23, D-6): navigation from alarms / aside buttons opens the tab but does not preselect vehicle, city, trip or partner.
