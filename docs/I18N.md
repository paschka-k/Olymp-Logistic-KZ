# UI texts: keyed string tables (FR-199) and Kazakh review (FR-220)

## Two ways to write a text

| | where the text lives | when to use |
|---|---|---|
| `LT('area.key')` | `platform-src/v6/strings/<ru\|de\|en\|kk>/<table>.json` (flat `{ "area.key": "text" }`) | **all migrated areas and every new screen** |
| `T('ru', 'de', 'en', 'kk')` | inline in the source | bridge: areas not migrated yet; calls with variable arguments |

Both work side by side, nothing breaks while an area is migrated. `LT('key', a, b)` fills `{0}`, `{1}` (no string
concatenation across languages: word order differs).

The build (`build-v6.mjs`) embeds only the language being built and **fails** when the four languages differ in their keys, when a DE / EN text
contains Cyrillic, or when `kk/_review.json` names a key that does not exist. A missing key at runtime shows `⟦key⟧` and is counted in `LT_MISS` (test
g4 asserts it stays empty on every screen of every role).

## Migrating an area (one file at a time)

```powershell
node tools/i18n/migrate.mjs platform-src/v6/screens/040-fleet.js --table fleet --prefix fleet
node platform-src/build-v6.mjs
```
The tool rewrites every all-literal four-argument `T(...)` to `LT('<prefix>.<slug of the English text>')` and appends the four texts to
`strings/<lang>/<table>.json`. Equal tuples share one key, equal slugs with different texts become `_2`, `_3`. Commit the migration
as its own change ("format only" style: no behaviour change); run the suite. `node tools/i18n/scan.mjs` lists how many `T()` calls each file still has.

**Migrated so far:** shell (`core.js`, `roles.js`, `001-shell-ext.js`, `002-a11y.js`, table `shell`) and the UI kit (`base/30-kit.js`, table `kit`).
**Next, in this order** (largest user-visible gain first): `010-dashboard`, `020-orders`, `030-dispatch`, `040-fleet`, `050-drivers`, `060-routes`, then the W/P/R areas.

## Kazakh completeness and review (FR-220, I-26)

* `node tools/i18n/scan.mjs --kk` lists Kazakh gaps: `missing` (fewer than four arguments), `equal` (same as Russian, usually a loanword or a proper
  name that is fine), `short` (Kazakh much shorter than Russian: a shortened text).
* Shortened texts are completed **in the keyed tables** (`strings/kk/*.json`) and listed in `strings/kk/_review.json` with
  `{ "status": "mt", "by": "...", "date": "YYYY-MM-DD" }` - a machine translation until a native speaker has checked it.
* Review workflow: `node tools/i18n/kk-review.mjs export > kk-review.csv` (key; ru; kk; status) -> the reviewer corrects the `kk` column and sets
  `status` to `reviewed` -> `node tools/i18n/kk-review.mjs import kk-review.csv` updates `strings/kk/*.json` and `_review.json`. Open any page as
  `kk.html?kkreview=1` to see every unreviewed text marked `[MT]`.
* Test g4 fails when `_review.json` lists a key twice or `reviewed` entries have no reviewer name.
